## 1.1 Maven 主要解决了什么问题？

* 依赖管理：在 `pom.xml` 中声明项目需要的依赖，Maven 会从仓库获取相应的 JAR 包，并处理这些依赖所需的其他依赖。

* 标准化的跨平台自动化项目构建方式

## 1.3 IOC 和依赖注入的作用是什么？

控制反转：IOC 

* 对象的创建控制权由程序自身转移到外部（容器）这里就是Spring容器
* 可以使用`@Component`注解将类交给IOC容器管理（是加在实现类上面而不是接口上面）

在本题中，Spring 扫描到带有 `@Service` 的 `EchoService` 和带有 `@RestController` 的 `EchoController` 后，会创建并管理相应的对象。

依赖注入：DI

* 容器为应用程序提供运行时所依赖的资源

* 具体是指当一个对象需要使用另一个对象时，由容器将它需要的对象传入。依赖注入是实现控制反转的一种方式。
* 使用`@Autowired`注解可以从IOC容器中找到该类型的bean，然后完成依赖注入

本题中`EchoController` 需要调用 `EchoService`，Spring 可以通过构造方法把 `EchoService` 对象传给它：

```java
private final EchoService echoService;

@Autowired
public EchoController(EchoService echoService) {
    this.echoService = echoService;
}
```

他们可以：

* 集中管理组件对象及其依赖关系。

* 减少业务代码中手动创建对象的工作
* 减少层级之间的耦合度，方便后续的维护



## 1.4 Controller、Service 和持久层（Mapper/DAO）在完整项目中分别负责什么？

Controller:控制层，接受前端发送的请求，对请求进行处理，并响应数据

service:业务逻辑层，处理具体的业务逻辑

dao：数据访问层（Data Access Object)（持久层），负责数据访问操作，包括数据的增删改查

前端给请求->controller->调用Service->调用dao取得数据

dao的实现可以有文本，网络，数据库

## 2.2 HTTP协议

* 超文本传输协议，浏览器与服务器之间数据传输的规则

* 基于TCP协议：面向连接，安全

* 基于请求-响应模型：一次请求对应一次响应

* HTTP协议是无状态的协议：对于事务处理没有记忆能力，每次的请求-响应是独立的

  * 缺点：多次请求之间无法共享数据
  * 优点：速度快

* URL:用来定位和访问资源的地址，平常说的“网址”就是一种 URL。

  * 比如：http://localhost:8080/hello?name=heima

    | 部分          | 含义                                |
    | ------------- | ----------------------------------- |
    | `http://`     | 使用 HTTP 协议                      |
    | `localhost`   | 访问本机                            |
    | `8080`        | 访问本机的 8080 端口                |
    | **`/hello`**  | URL 路径，指定要访问的接口          |
    | `?name=heima` | 查询参数，传入 `name`，值为 `heima` |
